Kebutuhan & Ruang Lingkup Proyek

Situasi Bisnis

Sebuah perusahaan digital membutuhkan peningkatan tata kelola data produk internal melalui modul backend yang andal, scalable, dan memiliki audit trail lengkap untuk kebutuhan operasional.

  • Pengelolaan varian produk (Fisik, Digital, Layanan).
  • Pencarian cepat berbasis multi-kriteria.
  • Pencegahan kehilangan data dan integritas inventaris.

  2. Pencarian Canggih: Algoritma filter & sort.

  4. Logging Audit: Pencatatan aktivitas modul.
  5. Pemantauan Performa: Metrik latensi & RAM.
  6. Dokumentasi Lengkap: Teknis & Pengguna.
Arsitektur & Desain OOP

Arsitektur Service-Repository

Pemisahan Tanggung Jawab (SoC)

  • Presentation Layer: Controller (`ProductController` & `ProductApiController`) hanya menangani HTTP I/O.
  • Validation Layer: Form Request (`StoreProductRequest`) dengan validasi otomatis dan pesan multibahasa.
  • Service Layer: `ProductService` mengelola aturan bisnis, transaksi DB, dan event logging.
  • Repository Layer: `ProductRepository` mengabstraksi kueri database Eloquent.

Kontrak Interface (DIP SOLID)

// Inversion of Control via AppServiceProvider $this->app->bind( ProductRepositoryInterface::class, ProductRepository::class ); $this->app->bind( ProductServiceInterface::class, ProductService::class );

Memastikan kode bersifat decoupled, mudah dilakukan unit testing (mocking), dan mematuhi prinsip SOLID.

Algoritma Pemrograman

Algoritma Pencarian & Filtering

Multi-Criteria Query Scope

Algoritma filter dinamis menggabungkan kriteria bersyarat tanpa kueri duplikat:

  • String Matching: Pencarian fleksibel pada SKU, Nama, dan Deskripsi.
  • Relational Filtering: Kategori dan Tipe Produk.
  • Price Range: Filter nilai minimum dan maksimum.
  • Stock Status: Kondisi in_stock, low_stock, dan out_of_stock.
  • Sanitized Sorting: Pengurutan dinamis aman SQL-Injection.

Optimasi Kompleksitas

Dengan menerapkan Composite B-Tree Index pada kolom pencarian utama:

Kompleksitas Tanpa Indeks: O(N) - Full Table Scan
Kompleksitas Dengan Indeks: O(log N) - Index Seek

Menghilangkan problem query lambat saat volume katalog mencapai puluhan ribu produk.

Ketahanan Sistem & Logging

Error Handling & Observabilitas

Custom Exception Handling

Menghindari generic error dengan melempar eksepsi spesifik domain:

  • ProductNotFoundException (404 Not Found)
  • DuplicateSkuException (422 Unprocessable)
  • InsufficientStockException (400 Bad Request)

Ditangkap terpusat di bootstrap/app.php dengan respon JSON/Redirect otomatis.

Dual-Logging Architecture

  • Monolog Channel: Log harian tersimpan di storage/logs/product-service.log.
  • Database Audit Trail: Tersimpan di product_activity_logs untuk ditampilkan di UI produk.
  • Alert Trigger: Peringatan otomatis ketika stok mencapai ambang batas (≤ min alert).
